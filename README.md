# Book search App

카카오 도서 검색 API를 활용해 만든 Android 앱입니다.  
도서 검색, 즐겨찾기, 정렬/필터 기능을 제공합니다.

[카카오 도서 검색 API 문서](https://developers.kakao.com/docs/latest/ko/daum-search/dev-guide#search-book)

## 빌드 방법

### API 설정

프로젝트를 빌드하기 위해 루트의 `local.properties` 파일에 아래 내용을 추가해주세요.

```properties
KAKAO_API_URL="https://dapi.kakao.com/"
KAKAO_API_KEY="KakaoAK "
```

`KakaoAK ` 뒤에 발급받은 REST API 키를 입력해주세요. 접두사 뒤의 공백과 값 양쪽의 큰따옴표는 유지해주세요.

### 실행 방법

1. Android Studio에서 프로젝트 루트를 열어주세요.
2. JDK 17과 Android SDK Platform 37을 준비하고, `local.properties`를 설정해주세요.
3. Gradle Sync를 실행해주세요.
4. `app` 실행 구성을 선택한 뒤 API 28 이상의 에뮬레이터 또는 기기에서 실행해주세요.

│   ├── database/              # Room DB, DAO, Entity, TypeConverter
│   ├── common/                # 앱 공통 CoroutineScope와 DI
│   ├── designsystem/          # 테마와 범용 UI 컴포넌트

| `core:domain` | 도메인 모듈로 `model`, `repository`, `usecase`, `error`를 구성했습니다. |
| `core:data` | 데이터 모듈로 `dataSource`, `repository`, `mapper`, `di`를 구성했습니다. |
| `core:network` | 네트워크 모듈로 API 인터페이스를, `dto`와 `di`에서 응답 모델과 네트워크 설정을 관리합니다. |

| `core:common` | 특정 화면에 속하지 않는 앱 공통 실행 환경을 공유하기 위해 분리했습니다. 현재 `di`에서 앱 단위 CoroutineScope를 제공하여, 화면을 떠나도 진행 중인 즐겨찾기 저장 작업을 유지하도록 합니다. |

| `core:ui` | 도서 관련 UI를 여러 feature에서 중복 구현하지 않고 공유하기 위해 분리했습니다. `com.example.ui`에서 도서 카드, 즐겨찾기 버튼, 검색·정렬·필터용 상단 UI와 표시 형식을 관리하며, 도메인 모델과 디자인 시스템 컴포넌트를 조합합니다. |

## 주요 구현 포인트

### 클린 아키텍처와 모듈 분리

화면, 도메인, 데이터 접근의 책임을 분리하는 클린 아키텍처를 적용했습니다. 화면의 ViewModel은 UseCase를 호출하며, UseCase는 도메인에 정의한 Repository 인터페이스에 의존합니다. 실제 API와 DB 접근은 `core:data`의 Repository 구현체에서 처리합니다.

`core:domain`은 순수 Kotlin/JVM 모듈로 구성했습니다. API DTO, DB Entity, 도메인 모델을 분리하고 Mapper를 통해 변환하여 각 계층의 데이터 표현이 화면에 직접 전달되지 않도록 했습니다.

### build-logic을 통한 빌드 설정 공통화

모듈마다 반복되는 SDK, Java/Kotlin 컴파일 대상, Compose, Hilt, 테스트 의존성 설정을 컨벤션 플러그인으로 분리했습니다. 각 모듈은 필요한 플러그인을 적용하고, 해당 모듈에 필요한 의존성과 설정만 추가합니다.

앱, Android 라이브러리, 순수 Kotlin 라이브러리, Compose, Hilt, feature용 플러그인을 구분했습니다. 라이브러리와 플러그인의 버전은 `gradle/libs.versions.toml`에서 공통으로 관리합니다.

구성 과정과 설정별 역할은 [build-logic 작업 기록](docs/build-logic.md)에 정리했습니다.

### 검색 화면

- 카카오 도서 검색 API를 사용하며 정확도순·발간일순 정렬을 제공합니다.
- 도서 목록에 정가와 판매가를 표시하고, 정가와 판매가를 기준으로 계산한 할인율을 함께 표시합니다.
- Paging으로 한 페이지에 20개씩 조회하고, 목록 끝에서 5개 앞에 도달하면 다음 페이지를 미리 요청합니다.
- 검색어나 정렬이 변경되면 새로운 검색 흐름으로 전환하고 목록을 맨 위로 이동합니다. 동일한 조건으로 다시 검색해도 새 요청으로 구분합니다.
- 당겨서 새로고침, 로딩 표시, 마지막 페이지 안내를 제공합니다. 검색 결과가 없으면 검색창 아래 콘텐츠 영역 중앙에 “검색 결과가 없습니다.”를 표시합니다.
- 검색 시 네트워크 오류가 발생하면 “네트워크를 연결해주세요” 문구와 확인 버튼이 있는 팝업을 표시합니다. HTTP 서버 응답 오류와 기타 오류는 화면에 안내합니다.
- 다음 페이지를 불러오는 동안에는 그리드 하단에 로딩을 표시합니다. 오프라인에서 로딩이 실패하면 연결 대기 문구를 표시하고, 네트워크가 복구되면 실패한 요청을 한 번 자동 재시도합니다. 연결된 상태에서 다시 실패하거나 서버 오류가 발생하면 수동 재시도 버튼을 제공합니다.
- 카카오 도서 검색 API의 페이지 제한에 맞춰 `MAX_PAGE = 50`을 설정했습니다. 50페이지에서 다음 페이지 키 생성을 중단하여 51페이지 요청을 방지하고, 목록 끝에 최대 50페이지까지 조회할 수 있다는 안내를 표시합니다.

### 즐겨찾기 화면

- Room에 저장한 도서를 표시하고, 제목 또는 저자로 검색할 수 있습니다.
- 검색 화면과 같은 도서 카드를 사용하여 정가, 판매가와 할인율을 표시합니다.
- 제목 오름차순·내림차순 정렬과 정가 기준 가격 필터를 제공합니다. 가격은 1만 원 미만, 1만 원대, 2만 원대, 3만 원대, 4만 원 이상으로 구분하며 필터 초기화도 제공합니다.
- DB 목록, 검색어, 정렬, 필터를 Flow의 `combine`으로 결합하여 화면 상태를 만듭니다.
- 즐겨찾기 존재 여부 조회와 추가·삭제를 하나의 Room 트랜잭션으로 처리하여 연속 클릭 시 조회와 변경이 엇갈리는 상황을 방지합니다.
- 앱 단위 CoroutineScope에서 저장을 수행하여 화면을 떠나도 진행 중인 저장 작업이 유지되도록 했습니다. `async/await`로 대기 중인 호출자에게 저장 실패를 전달합니다.
- 검색·즐겨찾기·상세 화면의 ViewModel에서 저장 실패를 처리하고 Snackbar로 안내합니다. 화면을 떠나 호출이 취소된 경우에는 해당 화면의 오류 안내까지 보장하지 않습니다.

### 상세 화면

- 선택한 도서의 표지, 제목, 저자, 출판사, 출간일, ISBN, 정가, 판매가, 소개를 표시합니다.
- 판매가 옆에 정가 대비 할인율을 표시합니다. 정가가 0보다 크고 판매가가 0 이상이면서 정가 이하인 경우에만 할인율을 계산합니다.
- 목록에서 선택한 도서 정보를 `SavedStateHandle`을 통해 전달합니다. 전달된 정보가 없으면 이전 화면으로 돌아가도록 처리했습니다.
- DB 응답 전에는 목록에서 전달받은 즐겨찾기 상태를 표시하고, 이후에는 DB의 ID 목록을 기준으로 갱신합니다.
- 현재 상세 화면의 백 스택 항목을 확인한 뒤 뒤로가기를 처리하여 중복 뒤로가기 호출을 방어합니다.
- 빈 문자열과 비어 있는 저자 목록은 `-`로 표시하고, 판매가가 음수이면 판매가 항목을 숨깁니다. 이미지 로딩 실패 시에는 대체 이미지를 표시합니다.

### 태블릿·폴더블 대응

검색·즐겨찾기 화면은 `LazyVerticalGrid`를 사용합니다. `CappedAdaptiveGridCells`에서 실제 사용 가능한 너비를 기준으로 열 수를 계산하며, 카드 최소 너비는 320dp, 최대 열 수는 3열로 제한했습니다.

| 목록 영역 너비 | 열 수 |
| --- | --- |
| 680dp 미만 | 1열 |
| 680dp 이상, 1008dp 미만 | 2열 |
| 1008dp 이상 | 3열 |

위 기준은 좌우 여백 각 16dp와 열 간격 8dp를 포함한 값입니다. 폴더블 펼침, 화면 회전, 분할 화면으로 사용 가능한 너비가 달라지면 열 수도 다시 계산합니다. 검색 목록의 재시도 및 마지막 페이지 안내는 모든 열을 차지하도록 구성했습니다.

### 빈 검색어와 공통 오류 안내

검색창에 포커스가 있으면 검색 아이콘 색상을 변경하고 닫기 버튼을 표시합니다. 닫기 버튼을 누르면 키보드를 숨기고 포커스를 해제합니다. 포커스가 해제되면 검색 아이콘 색상을 원래대로 되돌리고 닫기 버튼을 숨깁니다.

검색·즐겨찾기 화면에서 빈 문자열이나 공백만 입력한 상태로 검색을 제출하면 `검색어를 입력해주세요` 토스트를 표시합니다. 이때 검색 콜백을 호출하지 않고 키보드와 입력 포커스를 유지합니다.

즐겨찾기 저장 실패의 Snackbar 안내는 `core:designsystem`의 `ErrorHost`로 공통화했습니다. 특정 기능의 문자열 리소스를 컴포넌트 내부에서 참조하지 않고, 각 화면에서 `stringResource`로 읽은 메시지를 `message: String` 인자로 전달합니다.

검색 시 네트워크 오류는 같은 모듈의 공통 `PopupWidget`으로 안내합니다. 메시지와 버튼 문구를 인자로 받고, 취소·확인 버튼은 필요에 따라 표시할 수 있도록 구성했습니다. 정렬·필터 항목 선택에는 별도의 `SelectionPopupWidget`을 사용합니다.

AI가 작성한 플러그인을 바탕으로 개발을 진행하면서 필요한 라이브러리와 플러그인은 직접 추가했습니다. 구성 내용은 별도의 [build-logic 작업 기록](docs/build-logic.md)으로 남겼습니다.

### 기능 구현 후 코드 검토와 보완

기능 구현을 완료한 뒤 전체 코드에서 부족한 부분을 검토하도록 요청했습니다. AI가 제안한 수정 결과를 그대로 적용하는 데 그치지 않고, 기존 코드와 비교하여 호출 흐름, 역할 변경, 재사용 가능성, 중복 처리를 직접 확인했습니다.

1. **빠른 연속 클릭 시 즐겨찾기 토글 결과가 달라질 수 있는 문제**

   기존에는 Repository에서 즐겨찾기 존재 여부를 확인한 뒤, DataSource를 통해 DAO의 개별 추가·삭제 메서드를 호출하는 구조였습니다. AI는 조회와 추가·삭제를 DAO의 하나의 트랜잭션으로 묶어 처리하도록 변경했습니다.

   이 과정에서 AI는 `FavoriteDao`를 `interface`에서 `abstract class`로 변경했습니다.  
   직접 검토한 결과, Kotlin의 `interface`에도 본문이 있는 함수를 작성할 수 있고 Room은 해당 함수에 붙은 `@Transaction`을 처리할 수 있으므로, 트랜잭션 적용을 위해 DAO의 형식까지 바꿀 필요는 없다고 판단했습니다.  
   따라서 DAO를 `interface`로 되돌리고, `toggleFavorite()` 안의 조회와 추가·삭제를 하나의 트랜잭션으로 묶는 구현은 유지했습니다.

   수정된 코드를 검토하면서 토글 여부를 판단하고 실행하는 책임이 Repository에서 DAO로 이동했다는 점을 확인했습니다. 이에 따라 기존 토글 처리에서 사용하던 DataSource의 `addFavorite`, `removeFavorite` 메서드는 더 이상 필요하지 않지만, 코드에 남아 있다는 점도 확인했습니다. 해당 메서드는 이번 작업에서는 삭제하지 않았습니다.

2. **즐겨찾기 저장 실패 처리와 오류 UI의 재사용성**

   AI는 저장 실패를 ViewModel에 전달하고 화면에서 안내할 수 있도록 연결했으며, `core:ui`에 `FavoriteErrorHost`를 만들었습니다. 최초 구현에서는 컴포넌트 내부에서 특정 문자열 리소스를 참조하여 고정된 오류 문구를 표시했습니다.

   직접 검토한 결과, 오류 안내 컴포넌트가 특정 기능의 문구에 의존하기보다는 여러 화면에서 서로 다른 메시지를 받아 표시할 수 있어야 한다고 판단했습니다.  
   따라서 `core:designsystem`의 `ErrorHost`로 옮기고, `message: String` 인자를 받도록 변경했습니다.  
   각 화면에서 문자열 리소스를 읽어 전달하도록 하여 공통 컴포넌트와 화면별 메시지의 책임을 분리했습니다.

3. **빈 검색어 처리에서 불필요하게 추가된 중복 검사**

   빈 검색어 제출 시 토스트를 표시하고 키보드와 포커스를 유지하도록 수정하는 과정에서, AI는 검색 함수 내부에도 빈 값이면 바로 반환하는 검사를 추가했습니다.

   코드 검토 시 이미 UI에서 `textFieldState.text`가 빈 값인지 확인하여 분기하여  onBlankSearch(), onSearch()을 호출하고 있다는 점을 확인했습니다. 조건의 경우라면 onSearch가 호출되지 않는데 text 빈값일 경우 return 문이 추가 되어있습니다.

   중복 처리라고 판단하여 제거했습니다.

4. **페이징 자동 재시도 구현과 공식 문서를 통한 검증**

   “그리드뷰에서 페이징 중 오류가 발생하면 맨 아래 셀에 다시 조회하기 버튼 대신 로딩을 표시하고, 네트워크 연결을 자동으로 감지하면 어떨까요?”라는 요구사항을 전달했습니다.  
   AI와 동작을 검토한 뒤, 다음 페이지 요청 중에는 하단에 로딩을 표시하고 오프라인에서는 연결 대기 문구를 표시하도록 구현했습니다. 연결이 복구되면 한 번 자동 재시도하고, 연결된 상태에서도 실패하면 수동 재시도 버튼을 제공하도록 했습니다.

   구현된 코드를 확인하면서 Android Developers 공식 문서에서 네트워크 콜백의 각 메서드와 주의사항을 직접 살펴봤습니다.  
   AI가 작성한 `onCapabilitiesChanged()`에는 `network == manager.activeNetwork` 조건이 있었는데, `manager.activeNetwork`가 내부적으로 동기식 `getActiveNetwork()`를 호출한다는 점을 확인했습니다.  
   공식 문서에서는 콜백 안에서 동기식 `ConnectivityManager` 메서드를 호출하면 콜백 정보와 다른 시점의 값이나 `null`이 반환되는 경쟁 상태가 발생할 수 있으므로, 이러한 호출을 피하도록 안내하고 있었습니다.

   이 근거를 AI에게 전달하고 해당 비교 조건을 제거하도록 요청했습니다.  
   AI는 콜백으로 전달받은 `capabilities`를 직접 사용하도록 수정했으며, 함께 확인된 `onLost()` 내부의 동기 조회도 제거했습니다. 최초 상태 조회는 콜백 밖에서만 수행하고, 먼저 전달된 콜백 상태를 초기 조회 결과가 덮어쓰지 않도록 보완했습니다.  
   이 과정에서는 AI가 생성한 코드의 메서드 사용 방식이 공식 문서의 지침에 맞는지 직접 검증하고, 확인한 문제를 근거와 함께 전달하여 수정했습니다.

   참고 문서: [Android Developers — NetworkCallback.onCapabilitiesChanged()](https://developer.android.com/reference/android/net/ConnectivityManager.NetworkCallback#onCapabilitiesChanged(android.net.Network,%20android.net.NetworkCapabilities))

5. **검색 시 네트워크 오류 안내를 공통 팝업으로 변경**

   기존에는 검색 시 네트워크 오류가 발생하면 `SearchStatusWidget`을 통해 검색 화면 안에 연결 안내 문구를 표시했습니다.  
   이 안내를 팝업으로 표시하도록 변경하고 싶어 AI에게 수정을 요청했습니다. 네트워크 오류 팝업에는 “네트워크를 연결해주세요”라는 문구와 확인 버튼만 표시하도록 정했습니다.

   여러 화면에서도 사용할 수 있도록 메시지를 인자로 전달하고, 취소·확인 버튼은 필요에 따라 표시할 수 있는 공통 컴포넌트로 만들도록 요청했습니다.  
   기존 `PopupWidget`은 정렬·필터 항목을 선택하는 용도였으므로 `SelectionPopupWidget`으로 이름을 변경하고, `core:designsystem`의 공통 안내 팝업을 `PopupWidget`으로 구성했습니다.  
   검색 시 발생하는 네트워크 오류는 공통 팝업으로 안내하고, 다음 페이지 로딩 중 발생하는 오류는 기존 하단 안내와 자동 재시도 흐름을 유지하도록 했습니다.

6. **기획 관점의 검토를 통한 화면 동작 보완**

   “기획자 기준으로 검토하고 기획적으로 추가할 사항이 있으면 알려주세요”라고 AI에게 요청했습니다. 제안된 내용 중 필요한 항목을 직접 선택하고, 가격 처리 기준과 카드 표시 방식은 별도로 지정하여 수정을 요청했습니다.

   검색 화면과 즐겨찾기의 검색·필터 결과가 없을 때는 “검색 결과가 없습니다.”로 안내 문구를 통일했습니다. 검색 화면에서는 해당 문구를 검색창 아래 콘텐츠 영역 중앙에 표시하도록 했습니다. 즐겨찾기에 저장한 책이 아예 없는 경우에는 별도의 저장 안내 문구를 유지했습니다.

   즐겨찾기 화면에서 삭제한 뒤 Snackbar의 “실행 취소”로 가장 최근 삭제한 책을 복원할 수 있도록 했습니다. 복원 시에는 토글을 다시 호출하지 않고 저장 상태로 설정하여, 다른 화면에서 이미 다시 저장한 책이 삭제되지 않도록 구성했습니다.

   가격 필터는 판매가가 0 이상이면 판매가를 사용하고, 판매가가 음수이면 정가를 사용하도록 기준을 정했습니다. 또한 판매가가 정가보다 비싼 경우에는 목록과 상세 화면에서 정가와 할인율을 숨기고 판매가만 표시하도록 요청했습니다.
